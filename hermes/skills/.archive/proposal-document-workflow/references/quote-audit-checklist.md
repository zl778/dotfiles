# 报价文件审计清单

适用于：一个询价函 + 一个设备采购清单 + 多个供应商报价 DOCX。

## 1. 先确认当前文件

- 不要依赖先前生成的文件名；重新搜索项目目录。
- 记录实际文件名、供应商实名、供应商代号、品牌和型号。
- 建立映射：采购清单的公司A/B/C ↔ 报价文件的实际公司名。
- OneDrive 同步目录可能在审查期间改名或替换文件，审计必须基于当前实际文件。

## 2. 逐份审计

- 读取询价函的项目编号、预算、截止时间、报价有效期、交货期限、服务要求和全部技术条目。
- 读取 XLSX 每个供应商 sheet 的逐项型号、数量、单价、金额、备注和原始公式。
- 用 `python-docx` 逐段落、逐表格读取当前报价文件。
- 每一行技术响应标记为：已明确满足、待厂家书面确认、部分满足/待确认、存在偏差。
- `满足` 或 `无偏离` 仅在来源明确证明型号级能力时使用。

## 3. 重点技术陷阱

- “扩容后最高10Gbps”不能改写成“基础吞吐量≥8G”。
- 标配单电源 + 另购冗余电源不能直接写成主机标配双电源；要说明最终交付配置和兼容性。
- IPv4/IPv6 双栈、1:N 完全虚拟化、透明模式、威胁情报、ACG不能由一般防火墙功能自动推定。
- “SOP虚拟化”不能自动等同“1:N完全虚拟化”。
- 480G型号与资料中的960G描述冲突时，必须保留冲突并要求正式规格书确认。
- 家族页、相近型号或同系列页面不能替代精确型号证据。

## 4. 价格核算

逐项重算：

`不含税小计 = Σ(数量 × 单价)`

`含税总价 = 不含税小计 + 税金`

把源表公式结果、逐项完整结果、预算控制价并列报告。Excel公式可能漏掉最后一行，例如含300元跳线却使用54,850元合计；此时不能复制缓存公式，必须报告完整清单总价和预算风险。

## 5. 必交材料和内部一致性

检查：

- 营业执照；
- 原厂授权代理证明；
- 售后服务承诺；
- 3年原厂质保；
- 7×24支持；
- 4小时响应；
- 安装、调试、培训和培训记录；
- 运费、税费及服务费用是否已包含且不重复/漏计；
- 报价日期、截止日期、有效期、签章日期是否一致；
- 表格列数、合并单元格、金额列和备注列是否重复或错位。

## 6. 横向串标风险审查

提取三份文件的公司名、品牌、型号、金额、日期、元数据和正文段落。检查：

- 公司名或品牌互相混入；
- 型号、数量、价格错配；
- 长段落完全相同；
- 作者/最后修改者异常一致；
- 不同供应商出现同一处非通用错字或独特承诺。

报告应使用“未发现直接证据”“存在疑点”“需要结合外部证据核验”，不要仅凭共同模板或相似结构直接认定串标。

## 7. 交付前门槛

- 三份 DOCX 均能被 `python-docx` 重新打开。
- OfficeCLI resident 关闭后再执行 `officecli validate`，防止读到旧缓存。
- 任何修复都另存为 `*_审核修正版.docx`，保留原件和 `/tmp/` 备份。
- 最终报告分开写：价格合规、技术证据、材料完整性、串标迹象和硬性否决风险。
