# Model provenance and provider recovery notes

## What must be verified

For a named worker/Profile, verify three separate facts:

1. Profile config: effective `model.default`, `model.provider`, and `model.base_url`.
2. Authentication: the credential source belongs to that endpoint/provider.
3. Artifact provenance: the worker actually produced the output file; a coordinator-assembled file must not be reported as worker-generated.

A worker's model name in a launch command is not proof. Check the worker session/log and independently read the output artifact.

## Provider/endpoint mismatch pattern

A native provider pointed at a custom endpoint can authenticate with the wrong key. For example:

- `provider: deepseek` + `base_url: https://api.siliconflow.cn/v1` can send the DeepSeek-native key to SiliconFlow and return HTTP 401.
- `provider: nvidia` + the same SiliconFlow URL can send the NVIDIA key to SiliconFlow and return an invalid-key 401.
- `provider: custom` without a Profile-local provider mapping/API key can return an empty-key error.

Use a minimal no-tool request before dispatching long work. If the custom endpoint is unavailable, use a native endpoint and a model supported there; changing the model is preferable to silently claiming that a provider-qualified model still works.

Example recovery pattern:

```bash
# wukong native DeepSeek
hermes -p wukong config set model.provider deepseek
hermes -p wukong config set model.default deepseek-chat
hermes -p wukong config set model.base_url https://api.deepseek.com/v1

# writer native NVIDIA endpoint
hermes -p writer config set model.provider nvidia
hermes -p writer config set model.default minimaxai/minimax-m3
hermes -p writer config set model.base_url https://integrate.api.nvidia.com/v1
```

Then test each Profile:

```bash
hermes --yolo -p wukong chat -q '只回复：WUKONG_OK' -Q
hermes --yolo -p writer chat -q '只回复：WRITER_OK' -Q
```

Restart a running Gateway after changing its config and verify with `hermes profile show <name>` plus a real minimal request.

## Long-form artifact recovery

For 12,000+ Chinese-character Word tasks, do not combine source reading, drafting, docx creation, and verification in one worker call. Use temporary output paths and bounded phases. A background process may finish after the coordinator's first status check or may overwrite a synced target later, so freeze/backup the source and compare timestamps/content before accepting an artifact.

If a worker returns an empty log, reasoning-only output, HTTP 401/403, or no non-zero output file, mark that lane failed. Do not merge its claimed result. The coordinator may assemble from a verified base, but must disclose that the result was coordinator-assembled rather than independently generated by the failed worker.

For B when the user permits bullets, use them only for short parallel checks or response steps; keep long explanations as paragraphs and tables. Verify bullet XML in the resulting docx rather than relying on Markdown appearance.
