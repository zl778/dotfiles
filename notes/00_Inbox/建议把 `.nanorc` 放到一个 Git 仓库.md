配置的原则是：

- ✅ 兼容 **GNU Nano 8.x / 9.x**（Mac、WSL、Ubuntu VPS）
- ✅ 适合你的工作（Docker、YAML、Shell、Markdown、Python）
- ✅ 尽量避免不同发行版之间的兼容性问题
- ✅ 注释完整，以后自己维护也方便

## **Mac（Homebrew Nano）**

```nanorc
##############################################################################
# Nano Configuration
# For: macOS + WSL + Ubuntu VPS
# GNU Nano 8.x / 9.x
##############################################################################

##############################
# 界面（UI）
##############################

## 显示行号
set linenumbers

## 始终显示光标位置
set constantshow

## 右侧滚动指示器
set indicator

## 支持鼠标
set mouse

## 长行自动折行（不修改文件内容）
set softwrap

## 尽量在空格处分行
set atblanks

##############################
# 编辑
##############################

## 自动缩进
set autoindent

## Tab 显示宽度
set tabsize 4

## Tab 自动转换为空格（YAML/Python 推荐）
set tabstospaces

## 保存搜索历史
set historylog

## 记住上次编辑位置
set positionlog

##############################
# 安全
##############################

## 保存备份
set backup

## 建议先创建目录：
## mkdir -p ~/.cache/nano/backups
set backupdir "~/.cache/nano/backups"

##############################
# 语法高亮（Homebrew）
##############################

include "/opt/homebrew/share/nano/*.nanorc"
```

然后创建备份目录：

```bash
mkdir -p ~/.cache/nano/backups
```

# **Ubuntu / WSL**

唯一需要修改的是最后一行：

```nanorc
include "/usr/share/nano/*.nanorc"
```

其它内容可以完全一样。

# **我建议你把 Nano 当成「服务器编辑器」**

结合我们之前聊过的内容，你现在的工具链可以这样分工：

|**场景**|**工具**|
|---|---|
|VPS 上快速修改配置|**Nano**|
|WSL 修改脚本|**Nano**|
|Docker Compose|**Nano**|
|Nginx、SSH、systemd 配置|**Nano**|
|长时间编写代码、跨文件搜索、调试|Visual Studio Code（Remote SSH / WSL）|
|终端|Ghostty|

这样每种工具都发挥自己的优势。

## **我还有一个建议：同步一份配置到所有环境**

既然你已经同时使用：

- MacBook Pro（GNU Nano 9.1）
- WSL Ubuntu
- Ubuntu VPS

建议把 `.nanorc` 放到一个 Git 仓库（例如你的 `dotfiles`），然后在三台环境中统一使用。这样以后只维护一份配置即可，避免不同机器出现行为差异。对于经常在多台设备间切换的开发和运维工作，这是一个非常实用的习惯。
