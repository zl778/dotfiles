# 投标文件编制与交付工作流

## 一、项目启动与任务分工

收到招标文件后，首先建立项目工作目录，统一文件命名、版本编号、责任人和时间节点。

明确项目负责人、商务负责人、技术负责人、报价负责人、资料负责人、审核负责人和最终上传负责人。对于使用大模型辅助编制的项目，应同时明确主模型、各子 Agent、审核模型和汇总模型的任务边界，避免重复编写、内容冲突或遗漏。

建立投标任务清单和进度表，至少包括以下内容：

招标文件分析时间；
资料收集截止时间；
技术标初稿完成时间；
商务标和报价文件完成时间；
三轮审核时间；
电子签章时间；
上传测试时间；
正式上传截止时间；
打印、装订或 U 盘制作时间。

所有工作时间应以招标文件规定的投标截止时间为基准，预留必要的签章、上传失败、文件修改和重新生成时间。

## 二、优先测试投标系统和上传环境

在正式编制文件前，应优先进入招标平台、投标客户端或电子投标文件制作工具，测试实际上传环境。

重点确认以下事项：

平台登录和企业账号是否正常；
CA 数字证书、电子签章和驱动是否可用；
法人章、公章、授权章等印章是否能够正常识别；
投标文件制作工具的版本是否符合要求；
允许上传的文件类型、文件大小和文件数量；
是否要求上传 PDF、Word、图片、压缩包或专用格式文件；
是否需要分册、分页或分别上传；
文件名称是否有固定要求；
是否支持断点续传或重新上传；
是否需要进行加密、生成文件包或导出特定后缀文件；
是否存在在线填写、在线报价或在线签章环节；
是否能够正常完成模拟上传、文件校验和撤回操作。

根据测试结果，整理《上传环境测试记录》，提前发现客户端兼容、印章缺失、浏览器限制、文件过大、文件格式不符等问题。

原则上不得等到投标截止当天才首次测试上传。

## 三、招标文件拆解与要求梳理

对招标公告、招标文件、技术规范书、合同条款、补充通知、澄清文件、图纸和附件进行统一整理，确认所使用的是最终有效版本。

对招标文件至少进行以下四类分析：

### 1. 资格和废标项分析

提取所有可能导致资格审查不通过、符合性审查不通过或直接废标的内容，包括：

资质证书要求；
营业执照和经营范围要求；
人员资格要求；
业绩要求；
财务、纳税和社保要求；
联合体要求；
投标保证金要求；
授权委托要求；
签字盖章要求；
报价唯一性要求；
投标有效期要求；
交付期或工期要求；
实质性技术参数；
强制性响应条款；
禁止偏离条款；
文件格式和上传要求；
法律法规规定的其他否决条件。

形成《废标项及实质性条款核查表》，逐项注明原文位置、响应方式、责任人和最终文件所在位置。

### 2. 评分表分析

逐条拆解评分标准，形成评分响应矩阵。

评分响应矩阵至少包括：

评分项目；
评分分值；
评分标准原文；
得分条件；
需要提供的证明材料；
应放置的文件章节；
责任人；
预计得分；
风险点；
最终核验结果。

对于主观评分项，应分析高分档、中分档和低分档的区别，反向设计技术方案的章节结构、内容深度、数据支撑和图表形式。

### 3. 格式和封装要求分析

确认投标文件是否区分：

资格文件；
商务文件；
技术文件；
报价文件；
电子文件；
纸质文件；
明标文件；
暗标文件；
正本和副本；
单独密封文件；
开标一览表；
保证金材料；
演示文件或样品资料。

同时确认：

页面尺寸；
页边距；
字体字号；
行距和段距；
各级标题编号；
页眉页脚；
页码规则；
目录格式；
是否允许彩色内容；
是否允许使用公司名称、Logo、人员姓名或品牌标识；
是否要求连续页码；
是否要求骑缝章；
是否要求逐页签章；
是否要求指定位置签字；
是否需要分卷、分册、压缩或加密。

### 4. 合同和履约风险分析

除评分和废标条件外，还应重点分析：

付款条件；
履约保证金；
质保期限；
违约责任；
验收标准；
知识产权；
保密要求；
数据安全；
服务响应时间；
工期或交货期；
价格调整机制；
合同变更条件；
发票和税率要求。

对无法直接接受的条款，应尽早提出澄清或进行内部风险评估。

## 四、资料清单与缺口管理

根据招标文件要求，建立《投标资料清单》，将资料分为已有、待更新、待提供、待制作和不适用五类。

通常需要准备的资料包括：

营业执照；
资质证书；
许可证；
体系认证；
企业信用材料；
财务报表或审计报告；
纳税证明；
社保证明；
无重大违法记录声明；
法定代表人身份证明；
授权委托书；
被授权人身份证明；
人员简历；
人员证书；
劳动合同或社保证明；
项目业绩合同；
中标通知书；
验收证明；
用户评价；
产品检测报告；
软件著作权或专利；
厂家授权书；
售后服务承诺；
技术参数证明；
投标保证金凭证；
银行资信证明；
报价基础数据；
其他招标文件要求的证明材料。

每份资料应记录：

文件名称；
对应招标条款；
提供部门或人员；
有效期；
是否需要原件扫描；
是否需要盖章；
是否需要合并；
是否涉及脱敏；
最终放置位置；
当前完成状态。

对于缺失资料，应设置明确的补充时限和责任人，并持续跟踪。

## 五、总体响应策略和篇幅设计

正式编写前，应根据评分权重、项目复杂程度和文件限制，设计投标文件的整体篇幅和表达方式。

重点确定：

各分册的预计页数和字数；
各评分项对应的篇幅比例；
各级标题层级；
技术方案的章节结构；
图表数量；
流程图、架构图、组织图和进度图的使用位置；
证明材料引用方式；
商务内容和技术内容的边界；
重复内容的处理方式；
暗标文件中的匿名化规则；
正文、附件和证明材料之间的引用关系。

原则上，高分值评分项应给予更充分的篇幅和证据支持，低分值或形式性内容应简洁准确，避免平均分配篇幅。

如文件篇幅较大，可先生成一级、二级标题和详细写作提纲，经审核后再展开正文。

## 六、大模型和子 Agent 任务分配

将招标文件、评分表、格式模板、资料清单和项目背景整理为统一的输入材料，再分配给不同模型或子 Agent。

建议按以下方式分工：

主控 Agent：负责理解整体要求、分配任务、汇总成果和控制版本；

招标分析 Agent：负责提取评分项、废标项、资格条件和格式要求；

技术方案 Agent：负责总体技术方案、实施方案、服务方案和保障措施；

专项方案 Agent：分别负责编写项目组织、进度、质量、安全、培训、售后、应急、保密等专项内容；

商务响应 Agent：负责商务条款响应、资格材料目录、承诺函和偏离表；

报价辅助 Agent：负责检查报价结构、税率、合计关系和报价口径，但最终报价必须由授权人员确认；

图表 Agent：负责流程图、架构图、组织架构图、进度计划表和资源配置表；

审核 Agent：负责语言、逻辑、格式、合规性和评分覆盖检查；

核查 Agent：独立对照招标文件进行二次符合性核验，不直接沿用编写模型的判断。

每个 Agent 的任务应明确：

输入材料；
负责章节；
禁止编写的内容；
格式要求；
目标字数；
必须响应的评分项；
引用资料；
交付文件名称；
检查标准。

不得允许模型虚构企业资质、人员、业绩、案例、参数、证书、承诺或项目数据。所有事实性内容必须来源于已确认资料。

## 七、技术标和其他分册编制

按照确定的章节结构和格式模板编制文件。

技术标编制时，应重点做到：

每一项评分标准均有明确响应；
技术参数逐项对应；
方案内容与项目实际情况一致；
人员配置与人员资料一致；
项目进度与工期要求一致；
服务响应时间与承诺内容一致；
质量、安全、保密和应急措施具有可执行性；
图表与正文内容一致；
章节之间不存在相互矛盾；
不出现与其他项目无关的公司名称、地名、客户名称或项目名称；
不使用未经确认的模板残留内容；
暗标文件不出现可能识别投标人的信息。

商务标、资格文件和报价文件应同步推进，避免技术方案完成后才发现资质、人员、业绩或报价条件无法满足。

## 八、第一轮审核：基础质量检查

第一轮审核主要检查文本和格式质量。

检查内容包括：

错别字；
病句；
语法错误；
标点错误；
编号错误；
标题层级错误；
目录与正文不一致；
页码错误；
表格断页；
图片模糊；
字体字号不统一；
段落格式不统一；
多余空行和空白页；
重复章节；
遗漏章节；
模板残留文字；
项目名称错误；
招标人名称错误；
日期错误；
金额单位错误；
前后表述矛盾；
人员名称和岗位不一致；
图表与正文数据不一致。

本轮可由模型进行初步检查，但应由人工对重要信息进行复核。

## 九、第二轮审核：符合性与得分评估

第二轮审核应由独立核查模型和人工审核人员完成，重点评价投标文件与招标文件的符合性和预计得分。

审核内容包括：

资格条件是否全部满足；
废标项是否全部规避；
实质性条款是否逐项响应；
评分项是否全部覆盖；
评分证明材料是否充分；
评分内容是否放在正确章节；
评分项是否容易被评委找到；
技术参数是否存在负偏离；
商务偏离表是否准确；
承诺内容是否超出实际履约能力；
人员、业绩、证书是否真实有效；
文件签字盖章位置是否完整；
暗标要求是否完全满足；
不同分册之间是否存在冲突；
预计得分是否达到目标；
是否存在影响高分的薄弱项。

形成《符合性审查表》和《模拟评分表》，逐项记录：

当前响应情况；
预计得分；
扣分原因；
风险等级；
修改建议；
整改责任人；
整改完成情况。

## 十、第三轮审核：定稿前综合审查

第三轮审核以准输出稿为对象，进行全面定稿审查。

本轮应重点核对：

最终报价；
总价和分项报价；
税率；
大小写金额；
报价表之间的勾稽关系；
人员名单；
人员证书；
项目业绩；
合同金额；
服务期限；
项目名称；
产品型号；
技术参数；
图片和图表；
页码和目录；
附件顺序；
签字和盖章；
商务、技术和报价文件的一致性；
电子版和纸质版的一致性；
上传文件名称；
文件大小；
分册和分页方式；
正本、副本和电子文件数量。

报价内容必须由企业授权人员最终确认。大模型只能用于辅助检查，不得代替财务、法务或项目负责人作最终决策。

## 十一、元数据清理与最终文件生成

完成内容定稿后，生成最终输出文件。

对 Word、Excel、PDF、图片及压缩文件进行检查，清理不必要的元数据，包括：

作者；
最后修改人；
公司名称；
批注；
修订记录；
隐藏文字；
隐藏工作表；
文档属性；
模板路径；
超链接记录；
外部数据连接；
嵌入文件；
临时文件信息；
图片 EXIF 信息；
无关书签；
历史版本信息。

元数据清理后，应重新检查文件内容，避免因清理操作造成目录失效、页码变化、字体替换、图片丢失或签章失效。

应保留一份内部可编辑源文件和一份最终提交文件。最终提交文件生成后原则上不再直接编辑，如需修改，应回到源文件修改并重新执行审核和输出流程。

## 十二、电子签章和专用格式制作

按照招标平台要求完成签字、盖章、加密和专用格式文件制作。

重点核验：

法定代表人签字或签章；
授权代理人签字；
企业公章；
法人章；
骑缝章；
报价专用章；
指定页面签章；
电子签章是否有效；
签章后文件是否能够正常打开；
签章位置是否遮挡正文；
签章后页码和目录是否变化；
专用投标文件是否能够通过客户端校验；
加密密码或解密信息是否正确保存。

电子签章完成后，不应再使用普通 PDF 编辑工具修改文件，否则可能导致签章失效。

## 十三、不同设备和环境下的交叉验证

最终文件应在与正式上传尽量一致的环境中进行验证。

可分别使用不同电脑进行以下测试：

文件能否正常打开；
字体是否缺失；
页面是否错位；
图片是否显示；
目录是否正常；
签章是否有效；
专用投标文件是否能够识别；
压缩包是否能够正常解压；
文件名称是否乱码；
U 盘拷贝后文件是否损坏；
平台客户端是否能够正常读取；
不同分册是否上传至正确位置。

不同电脑仅用于兼容性和完整性验证，不得通过修改作者信息、设备信息或其他方式规避平台监管、串标检测或合规审查。

## 十四、正式上传和上传后复核

正式上传时，应由至少两人共同操作或复核。

上传过程中重点确认：

登录账号和投标项目正确；
标段正确；
文件上传位置正确；
文件版本正确；
报价金额正确；
文件上传完整；
平台校验通过；
签章验证通过；
加密成功；
提交状态显示成功；
投标回执或上传凭证已保存；
平台显示的文件名称、大小和上传时间正确。

上传完成后，应重新登录平台检查投标状态，并保存：

上传成功截图；
投标回执；
文件校验结果；
平台提示信息；
上传文件清单；
最终提交时间；
操作人员记录。

在投标截止时间前，如平台允许撤回和重新上传，应避免无必要地反复修改。确需重新上传时，必须重新完成版本核对和上传后复核。

## 十五、纸质文件、打印和 U 盘制作

如招标文件要求提交纸质文件或 U 盘，应按照最终电子版进行制作。

打印前确认：

纸张规格；
单双面要求；
彩色或黑白要求；
正副本数量；
装订方式；
封面和书脊；
页码；
签字盖章；
骑缝章；
密封方式；
外包装标识；
递交地址；
递交时间；
递交人员身份证明。

U 盘制作时，应使用可靠介质，复制完成后重新打开并校验文件。必要时准备主用和备用 U 盘，但应严格按照招标文件要求提交，避免放入无关文件。

纸质版、U 盘版和平台上传版应保持内容一致。若招标文件规定不一致时以某一版本为准，应按其规定执行。

## 十六、项目归档和复盘

投标结束后，应对全部文件进行归档。

归档内容包括：

最终招标文件；
澄清和补充文件；
招标分析表；
评分响应矩阵；
废标项核查表；
资料清单；
各轮审核记录；
最终源文件；
最终提交文件；
电子签章文件；
专用投标文件；
报价确认记录；
上传回执；
提交截图；
纸质版清单；
快递或递交凭证；
项目复盘记录。

对中标或未中标结果进行复盘，分析：

实际得分；
扣分原因；
竞争对手差距；
技术方案薄弱点；
商务资料缺口；
报价偏差；
审核流程问题；
上传和交付问题；
可复用模板；
下次项目改进措施。

通过持续复盘，逐步形成企业自己的投标知识库、资料库、案例库、技术方案库和审核规则库。

# 推荐的总体流程

项目启动  
→ 上传环境预测试  
→ 招标文件拆解  
→ 废标项和评分项提取  
→ 资料清单及缺口跟踪  
→ 篇幅和格式设计  
→ 模型及子 Agent 分工  
→ 技术标、商务标和报价文件同步编制  
→ 第一轮基础质量审核  
→ 第二轮符合性和模拟评分审核  
→ 内容整改  
→ 第三轮定稿综合审核  
→ 元数据清理  
→ 电子签章和专用文件生成  
→ 多设备交叉验证  
→ 正式上传  
→ 上传结果复核  
→ 打印、装订或 U 盘制作  
→ 文件递交  
→ 项目归档和复盘
:::

这套流程可以直接作为企业内部的《投标文件编制作业指导书》基础版本使用，也可以进一步拆分成操作清单、责任分工表和三轮审核表。
