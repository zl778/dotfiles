# Hermes 会话分叉与任务插入规则


## 一、什么时候用 `/new`

当你发现当前会话里的新话题和主线不一致、容易把讨论搅乱时，用 `/new` 开新会话。

适合场景：
- 讨论多 Agent 方案时，临时切到 Kanban 实操
- 当前问题已经讲完，想开始一个完全新话题
- 不希望新话题污染旧上下文

使用方式：
```text
/new
```

## 二、什么时候用 `/branch`

当你想保留当前会话主线，同时分出一条分支继续试探或讨论时，用 `/branch`。

适合场景：
- 想保留原会话不丢
- 想在同一主题上开一条旁路
- 想做对比式讨论

使用方式：
```text
/branch
```

## 三、什么时候用 `/queue`

当你现在正在做的任务还没完成，但你临时想到一个后续任务，且这个后续任务属于同一上下文时，用 `/queue`。

适合场景：
- 当前任务的补充点
- 同一主题下的下一步操作
- 不想打断当前执行

使用方式：
```text
/queue 任务内容
```

## 四、什么时候用 `/steer`

当你希望在当前任务执行完当前工具调用后，再插入一条指令去轻微修正方向时，用 `/steer`。

适合场景：
- 不是新任务，只是补充约束
- 想让 Hermes 按你的新要求调整下一步
- 不想立即打断当前流程

使用方式：
```text
/steer 任务内容
```

## 五、回到之前话题的方法

如果你已经用了 `/new`，想回到之前的话题：

1. 先给主线会话起标题
```text
/title 多Agent方案
```

2. 开新会话
```text
/new
```

3. 回来时用标题恢复
```text
/resume 多Agent方案
```

如果没起标题，也可以先查看历史会话：
```text
/history
```
或
```text
/sessions
```

然后再用会话名或 ID 恢复：
```text
/resume <会话名或ID>
```

## 六、最实用的判断规则

- 新主题，且容易打乱主线 → `/new`
- 旁路试探，但不想丢主线 → `/branch`
- 同一任务里的补充内容 → `/queue`
- 同一任务里的轻微调整 → `/steer`

## 七、推荐习惯

- 重要主线先 `/title`
- 临时新话题用 `/new`
- 任务补充优先 `/queue` 或 `/steer`
- 需要对照和回溯时用 `/branch`

## 八、总结

一句话记忆：

- `/new`：开新会话
- `/branch`：开分支
- `/queue`：排到后面
- `/steer`：轻微修正方向
